# 洞穴巡测封控与补测台

## 启动

```bash
npm install
npm start
```

默认地址：http://localhost:3912

数据保存在 `data/db.json`，后续可以继续增量迭代。

## 业务规则

- **常规巡测额度**：每个样点每天只准一条常规巡测，重复登记会被拒绝。
- **暂停开放留档**：暂停开放的样点只能留档，不占常规额度，也不得改变保护状态；留档记录可更正读数但不触发任何封控变更。
- **游客干扰补测**：标记游客干扰后建立未闭环补测（同一样点重复标记沿用首次记录），期间该样点保持重点保护且状态锁定，其他样点不受影响。
- **补测闭环**：补测须由不同人员完成（原巡测人员不能补测），重复提交沿用首次记录；连续两次读数一致才能关闭，闭环后原巡测转为已复查、状态锁定解除。
- **更正重判**：原巡测更正后旧结论失效，按更正值重判封控——超差则转入重点保护，恢复正常且无未闭环补测则解除封控。

判定阈值（温度/湿度/CO2 相对基准的容差）在 `project.config.js` 的 `judge` 中配置。

## 校验

```bash
node scripts/smoke.mjs
```

使用独立临时数据库启动实例，端到端验证以上全部规则。
